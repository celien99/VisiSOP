This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

VisiSOP is a clean full-stack skeleton: FastAPI + SQLModel + PostgreSQL on the backend, React 19 + Vite + TanStack Router/Query + Tailwind/shadcn on the frontend. The built frontend is served by FastAPI on the same origin, and the TypeScript API client is generated from the backend's OpenAPI schema. Python 3.14 managed with `uv`; JS with `bun`.

There is no domain logic: the only API endpoint is `/api/utils/health-check/`, and the frontend is a single page. Add models in `backend/app/models.py`, routes in `backend/app/api/routes/`, and pages in `frontend/src/routes/`.

The architecture baseline is `docs/AI_SOP_Platform_Architecture_v2.0.md` (how the system runs); `docs/AI_SOP_Architecture_Design_v1.1.md` holds the strict constraints v2.0 does not expand (transition matrix, execution resolution, retention). `docs/implementation/README.md` splits them into work packages with repository paths and records decisions the baselines leave open; read the matching brief before implementing a package.

## Setup

```bash
docker compose up -d db
cd backend
uv sync
uv run bash scripts/prestart.sh          # alembic upgrade head
uv run fastapi dev                       # API at :8000, docs at /docs
```

In another terminal, from the repo root:

```bash
bun install
bun run dev                              # Vite at :5173
```

Alternatively run everything in Docker: `docker compose run --rm backend bash scripts/prestart.sh` then `docker compose watch` (app at :8000). Stop any local `fastapi dev` first because both bind port 8000.

## Commands

### Tests

```bash
# Backend (needs PostgreSQL running; coverage is generated in backend/htmlcov)
cd backend && uv run bash scripts/test.sh

# One backend test
cd backend && uv run pytest tests/api/routes/test_utils.py::test_health_check

# Frontend E2E (Playwright starts Vite automatically at :5173)
cd frontend && bunx playwright test
```

`bash scripts/test.sh` from the repo root builds and tears down the whole Compose stack. CI enforces 90% backend coverage (`--fail-under=90`).

### Lint / format / type check

```bash
uv run prek install -f          # install Git hook once, from repo root
uv run prek run --all-files     # run all checks manually

cd backend
uv run ruff check app && uv run ruff format app
uv run mypy app && uv run ty check app          # both are strict
# or: bash scripts/lint.sh / bash scripts/format.sh

bun run lint                    # biome check --write --unsafe on frontend
```

Biome ignores `frontend/src/client/**`, `frontend/src/components/ui/**`, and `frontend/src/routeTree.gen.ts` — these are generated/vendored.

### Database migrations

```bash
cd backend
uv run alembic revision --autogenerate -m "Add ..."
uv run alembic upgrade head
```

Commit the generated revision. `scripts/prestart.sh` runs `alembic upgrade head`.

### Regenerate the TypeScript API client

```bash
bash ./scripts/generate-client.sh    # from repo root
```

This imports `app.main` to dump OpenAPI to `frontend/openapi.json`, runs `bun run --filter frontend generate-client` (hey-api), then lints. Run it whenever routes or models change the schema and commit `frontend/src/client/**`.

## Architecture

### Backend

- `app/main.py` — builds the app, CORS for `FRONTEND_HOST`, mounts the API at `settings.API_PREFIX` (`/api`), and serves the built SPA from `app/frontend` via `app.frontend("/")`.
- `app/api/main.py` — aggregates routers. Add new routers here.
- `app/api/deps.py` — `SessionDep` (database session dependency).
- `app/models.py` — SQLModel models. It currently only re-exports `SQLModel` so Alembic autogenerate has a metadata target; add table models here.
- `app/core/config.py` — pydantic-settings `Settings`, reading the **root** `../.env` relative to the backend working directory. `DATABASE_URL` is rewritten to the `postgresql+psycopg://` driver.
- `app/core/db.py` — engine. Tables come from Alembic, not `create_all`.
- The route unique-ID function (`{tag}-{name}` in `app/main.py`) is what hey-api turns into frontend service names such as `UtilsService.healthCheck`. Every router needs a tag, and changing a tag renames generated client services.

### Frontend

- Routing is file-based via TanStack Router: files in `src/routes/` map to URLs; `src/routeTree.gen.ts` is generated by the Vite plugin and must not be edited. `_layout.tsx` is the app shell (header, theme switch, footer).
- All API calls go through the generated client in `src/client` (`@/client`). It is configured in `src/main.tsx` with `baseURL = VITE_API_URL ?? ""`.
- UI: shadcn/ui components live in `src/components/ui`; app components are grouped by domain under `src/components`. `@` aliases `src`.
- Vite builds into `../backend/app/frontend` with `emptyOutDir`, so `cd frontend && bun run build` produces exactly what FastAPI serves.

### Tests

- Backend: pytest with `TestClient`; `tests/conftest.py` provides the `client` fixture.
- Frontend: Playwright specs in `frontend/tests`; the config starts Vite automatically.

## Code quality — required for every change

High code quality is non-negotiable. Use these skills as part of normal work, not as an afterthought:

- **`/ponytail:ponytail`** (default working mode) — laziest solution that _works_s comments, defensive try/catch on trusted paths, `any` casts that paper over types, deep nesting that should be early returns, anything inconsistent with the surrounding file.
- **`/code-review`** — run on the diff **before merging**; fix the findings (use `/code-review ultra` for branch-wide cloud review).
- **`/simplify`** — quality-only pass for reuse/simplification/efficiency when not hunting bugs.
- **Superpowers**: `systematic-debugging` (root cause before any fix), `test-driven-development` (test-first for features/bugfixes), `verification-before-completion` (run the command and show real output before claiming done), `requesting-code-review` before merge.
