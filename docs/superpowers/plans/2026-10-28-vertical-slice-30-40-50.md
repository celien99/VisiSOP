# VisiSOP Vertical Slice (30 + 40 + 50) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On one Windows machine, a HIKROBOT MV-CH120-20GC GigE camera feeds a native runtime that detects a bottle in two configured zones, posts `VisionEvent`s, and drives a published `bottle_transfer` SOP through the FastAPI/PostgreSQL engine; the React wall, station detail, and execution detail show live preview, process state, evidence, alarms, and review with every transition auditable.

**Architecture:** Three processes share one machine: FastAPI on `:8000`, Vite on `:5173` (or the built SPA served by FastAPI), and the native Python runtime on `:8001`. PostgreSQL (Docker Desktop) is the sole authority. The runtime only reports observations; the backend verifies evidence, resolves the execution, runs the pure `sop_engine`, and commits step/execution/alarm/audit/outbox rows in one transaction. The WebSocket only signals a refetch.

**Tech Stack:** Python 3.14 backend (FastAPI, SQLModel, PostgreSQL, Alembic), Python ≥3.12 shared packages (`contracts`, `sop_dsl`, engine), Python 3.12 runtime (OpenCV, `harvesters`/MVS GenTL, ONNX Runtime), React 19 + Vite + TanStack Router/Query, Playwright, `uv`, `bun`, Docker Desktop.

## Global Constraints

- **Platform:** Windows 10/11, one machine. Shell scripts run in Git Bash; `.gitattributes` keeps `*.sh` at LF. No macOS paths, no `open`, no `/tmp` assumptions in committed code; use `pathlib`.
- **Python:** backend `>=3.14`; `contracts` and `sop_dsl` `>=3.12`; runtime `>=3.12,<3.13`. The runtime is a **standalone uv project** with a path dependency on `../contracts` — not a workspace member (ADR-0002). This is the only way one repo can build a 3.14 backend and a 3.12 runtime without a shared environment.
- **Ports/prefixes:** backend `:8000`, API prefix `/api`, WebSocket `/api/ws`; Vite `:5173`; runtime `:8001`; preview `GET /stream/{camera_id}`, snapshot `GET /snapshot/{camera_id}`, health `GET /health`.
- **Time:** every stored or wire datetime is UTC-aware. Domain functions take `now`; never call `datetime.now()` in `app/domain`. PostgreSQL columns are `TIMESTAMPTZ`.
- **Vocabulary:** statuses, reason codes, roles, processing results come from `contracts.enums` / `app.domain.sop.model`. Do not add a status string anywhere else. Alarm categories are `PROCESS_COMPLIANCE`, `VISION_QUALITY`, `DEVICE_HEALTH`, `DATA_INTEGRITY`, `SYSTEM`; severities `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`; alarm statuses `OPEN`, `ACKNOWLEDGED`, `RESOLVED`. Review decisions are the closed set in Task 1.
- **Authority:** PostgreSQL is the only authority for process state. The runtime does not decide completion, availability, or pass/fail. The frontend renders backend statuses/reason codes/allowed actions; it never derives SOP state.
- **Evidence:** runtime writes `EVIDENCE_DIR/tmp/{event_id}.jpg`; backend validates path/hash/dimensions, moves to `EVIDENCE_DIR/evidence/{evidence_id}.jpg`, and only `AVAILABLE` assets may be shown as evidence or cited in a review. A preview is not evidence.
- **Four facts stay separate:** visual observation, process compliance, system/device health, evidence availability. `NEEDS_REVIEW` is a first-class state, not a red error. Confidence is not a pass rate.
- **No fake production data.** The demo SOP/station/camera are labeled demo seed data (`st-01`, `cam-01`, `runtime-01`, SOP key `bottle_transfer`).
- **Frontend:** `--vs-*` tokens only; no rounded corners/shadows/gradients; square corners, 1px lines; status colors only for status. Use the generated client from `src/client`; no manual `fetch`/`axios`, no handwritten wire enums, no `any`, no type assertions.
- **Quality gates:** `ruff check`, `ruff format --check`, strict `mypy`, `ty check`; backend coverage ≥90% (`bash scripts/test.sh`); `bun run lint`; `bun run build`; Playwright. Run `bash ./scripts/generate-client.sh` after any route/schema change; commit `frontend/src/client/**` with the change; no diff at the end.
- **Commits:** one conventional commit per task (`feat`, `fix`, `refactor`, `docs`, `build`, `chore`). Add the repository's current attribution trailer if the harness requires one.
- **Single-process shortcuts are explicit:** one API worker, in-process WS registry and outbox dispatcher, one timeout worker. Code comments use `shortcut: <limit>, <when to upgrade>`.

## Review Focus

Each line names the input/failure mode most likely to hurt a real operator, and the task whose tests pin it.

1. **Duplicate delivery after a network timeout.** The runtime posts an event, the backend commits, the HTTP response is lost, and the runtime retries the same `event_id`. Expected: `DUPLICATE`, no second step transition, no second evidence link, no duplicate alarm. — Task 9.
2. **Preview dies while the process is fine.** Camera unplugged or runtime stopped: the wall card must keep showing process step/status/health and say `无信号`/`预览不可用`; it must not show a stale frame as live or imply the step stopped. — Tasks 14, 16.
3. **Late or out-of-order zone event.** A pickup-zone event arrives after the target step is active. Expected: no regression of `pick_bottle`, no completion of `place_bottle`, an `OUT_OF_ORDER` alarm visible; not a false pass. — Task 9.
4. **Evidence missing or unverified.** A step with required evidence completes, but the file is absent or `PENDING_VERIFY`. Expected: the step goes `NEEDS_REVIEW`/`EVIDENCE_MISSING`, evidence is shown unavailable, and a review needs operator + reason before it can be closed. — Tasks 9, 15.
5. **Pause/resume vs timeout.** A paused execution must never time out; resuming extends active deadlines by the paused duration (not reset to the full timeout), and a timeout exactly at the resume boundary resolves deterministically. — Tasks 7, 11.

## Decisions Recorded by This Plan

These are written as ADRs in Task 1; the plan depends on them.

- **ADR-0002 — runtime is a standalone uv project; shared packages floor at 3.12.** The backend stays 3.14; `contracts`/`sop_dsl` are importable from 3.12; the runtime has its own `uv.lock`.
- **ADR-0003 — optional event execution hint + closed review decisions.** `VisionEvent.execution_id: str | None = None` lets the resolver take an explicit path; `RoutedSOPEvent` still requires it. Review decisions are `MARK_COMPLETED` and `MARK_FAILED`; a review also requires an operator, a reason, and (optionally) evidence IDs. No `pass`/`fail` semantics are invented.
- **Demo fixture, not a generic catalog.** `bottle_in_pickup_zone` and `bottle_in_target_zone` are B1 event types with strict `ZoneObjectAttributes`; they are not added to the default catalog. B2 replaces them with parameterized catalog instances.
- **Bulk runtime-state endpoint.** `GET /api/stations/runtime-state` is an extension to the 30 brief so the wall loads in one request instead of N+1 station calls. It is declared before `GET /api/stations/{station_id}`.
- **Alarm dedup key.** Alarms carry a computed `dedup_key` with a partial unique index over non-`RESOLVED` rows; repeated intents update `last_seen_at`/`occurrence_count`.
- **Evidence `MISSING` asset.** A declared evidence ref whose file is absent creates an `EvidenceAsset(status=MISSING)` so the UI can say “missing” explicitly instead of rendering nothing.
- **In-process outbox/WS.** The dispatcher and WS registry live in the API process; the DB outbox remains the transport record. Single API worker until upgraded.
- **Review/alarm identity.** Stage 1 has no auth. Review and alarm actions take an explicit `operator` string from the caller; the UI asks for it; the API never defaults a fake operator.
- **One active execution per station.** “Active” includes `RUNNING`, `PAUSED`, and `NEEDS_REVIEW`; starting another returns 409 until the review closes it.

`useExecutionSocket`:
- Build the URL from `VITE_API_URL` (http→ws, https→wss) or `window.location`; append `/api/ws`.

- Deduplicate the last 100 `message_id`s; on a new message call `onMessage(type)`.
- Reconnect backoff `[1000, 2000, 4000, 8000, 16000, 30000]`, reset on open; clean up `onclose`/timers on unmount.
