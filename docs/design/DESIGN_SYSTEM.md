## 1. 原则

1. **一屏一个主体。** 监控墙的主体是画面；看板的主体是时间曲线；详情页的主体是证据。谁都不是"六个 KPI 卡"。
2. **画面是数据。** 相机帧、ROI、时间戳、分辨率都是事实，要按事实排版；不许把画面当装饰背景、不许做假直播。
3. **信号色只表示状态。** 绿/琥珀/红/灰只出现在状态、告警、处置上。品牌与结构用骨白与石墨，不用信号色。
4. **事实不合并，结论不由前端产生。** 四类事实分开呈现；判定、原因码、允许动作都来自后端。
5. **方形、结构线。** 无圆角、无卡片阴影、无渐变。分隔用 1px 线，层级用底色与留白。
6. **数字用窄体。** Archivo 的 `wdth 62%` 只给数字、ID、时间戳、大标题；正文回到常规宽度。
7. **只在变化处动。** 120–180ms，只动 `opacity` / `transform` / `color`。没有呼吸灯、扫描线、数字滚动。
8. **密度里留空气。** 10px 墙体、20px 面板内边距、14px 面板间距；密不等于挤。

### 2.2 状态色（保留色）

一色一义。**颜色永远不是唯一载体**：状态必须同时有图标或文字（`✓ 正常`、`⚠ 待确认`、`✕ 异常`、`— 离线`）。

| Token | 值 | 语义 | 典型用法 | 禁止 |
|---|---|---|---|---|
| `--vs-ok` | `#35a15b` | 已完成、健康、在线 | 卡角状态章、进度轨已完成段、健康点 | 表示"合格率"或给数字装饰 |
| `--vs-warn` | `#e9a227` | 待确认、等待人、低于目标 | 待确认章、ROI 框、处置条 | 表示失败 |
| `--vs-crit` | `#d9482f` | 工艺不合规、破坏性动作 | 异常章、异常处置条 | 表示系统/设备故障 |
| `--vs-off` | `#6d7779` | 无信号、不可用、跳过 | 离线章、断线画面、禁用 | 表示工艺失败 |
| `--vs-ok-ink` | `#7fd39a` | 绿在深底上的文字版 | "作业正确"小字 | 大面积填充 |
| `--vs-warn-ink` | `#ffd392` | 琥珀文字版 | 待确认标题、等待时长 | 大面积填充 |
| `--vs-crit-ink` | `#ff9d88` | 红文字版 | 异常标题 | 大面积填充 |
| `--vs-off-ink` | `#b7bfbc` | 灰文字版 | 离线说明 | 状态章填充 |

**实底状态章**：`ok` / `warn` / `crit` 用 `--vs-on-status`（近黑）做文字；`off` 用白字（近黑在 `#6d7779` 上只有 4.2:1）。实底只用于**状态章**和**处置条**，其余地方用 1px 语义边框 + `--vs-surface-2` 底 + ink 文字。

> 状态色不得做成多系列图表。红/绿/琥珀在 protan/deutan 下分离度不足（实测 ΔE 3–5，低于 8 的门槛），所以图表一律单色相；状态只以"图标 + 文字"出现在章、表格与进度轨上。

### 2.3 图表色

| Token | 值 | 用途 |
|---|---|---|
| `--vs-series` | `#4b93d8` | 唯一的数据系列色（线、面积、条） |
| `--vs-series-track` | `#1c2325` | 条形/仪表的底槽 |
| `--vs-series-area` | 28% 透明 | 面积图填充 |

已在 `--vs-surface` 上验证：亮度 L 0.60（带内）、色度达标、对比 5.5:1。**不要**再引第二个系列色号；两个量就画两张图，或换成单色相的深浅（sequential）。

### 2.4 对比度（实测，底色 `--vs-surface`）

| 前景 | 对比度 | 结论 |
|---|---|---|
| `--vs-ink` | 14.5:1 | 正文/关键值 |
| `--vs-ink-secondary` | 8.3:1 | 次级文字 |
| `--vs-ink-muted` | 4.5:1 | 小字元数据的下限 |
| `--vs-warn` / `--vs-warn-ink` | 8.2 / 12.7:1 | 可做文字 |
| `--vs-crit` | 4.2:1 | **只做填充/边框**；文字用 `--vs-crit-ink`（8.9:1） |
| `--vs-ok` | 5.4:1 | 可做文字 |
| `--vs-off` | 3.9:1 | **只做填充**；文字用 `--vs-off-ink`（9.5:1） |
| `--vs-series` | 5.5:1 | 可做文字与图例 |
| `--vs-line` / `--vs-grid` | 1.3 / 1.2:1 | 仅装饰线，不承载唯一信息 |

**规则**

- 深色界面里"提亮"不等于"变淡"：小字一律用 `*-ink` 变体，不要靠透明度压暗。
- 不用渐变、发光、玻璃拟态、彩色阴影。唯一允许的纹理是监控墙离线段的对角斜纹。
- 图片上压字必须有渐变压暗层（`--vs-void` 起 84% 透明到 0），且只在文字带内。
- 不做浅色主题。界面本来就是控制室暗场；强行做浅色会破坏画面与界面的对比关系。

## 3. 字体

### 3.1 家族

| Token | 字体 | 角色 |
|---|---|---|
| `--vs-font-sans` | `Archivo`（变体，wdth 62–125 / wght 100–900）→ `PingFang SC` / `Hiragino Sans GB` / `Noto Sans CJK SC` / `Microsoft YaHei` | 全部文字 |
| `--vs-stretch-condensed` | `62%` | 数字、ID、时间戳、KPI、大标题 |
| `--vs-stretch-label` | `78%` | 字标、分组标签 |
| `--vs-stretch-normal` | `100%` | 中文正文、说明 |

- 自托管 `frontend/public/fonts/archivo-var.woff2`（OFL），**不请求 Google Fonts**：工业现场常常离线。
- 没有等宽字体。机器事实靠**窄体 + 表格数字**识别，不靠第二种字族。
- 中文没有窄体字形，`font-stretch` 对 CJK 无效；不要对中文块整体设窄体，否则会出现回退不一致。

### 3.2 字阶

| Token | 大小 | 字重 | 用途 | 约束 |
|---|---|---|---|---|
| `--vs-text-hero` | 46px | 700 窄体 | KPI 数值 | 每面板最多 1 个 |
| `--vs-text-display` | 28px | 700 窄体 | 屏幕标题、时钟 | 每屏 1 个 |
| `--vs-text-title` | 17px | 700 | 画面卡判定、案卷标题 | — |
| `--vs-text-heading` | 15px | 700 | 面板标题、工位名 | — |
| `--vs-text-body` | 13px | 400/600 | 中文正文、表格 | 桌面下限 |
| `--vs-text-meta` | 12px | 400/700 | 轴标签、图例、脚注 | 小字元数据 |
| `--vs-text-micro` | 11px | 700 | 状态章、画面角标 | — |
| `--vs-text-nano` | 10px | 400 | 分辨率/帧率 | **只做辅助，不承载事实** |

- 所有数字加 `font-variant-numeric: tabular-nums`，否则时间戳会跳动。
- 字重只用 400 / 600 / 700 三档。
- 一个面板内最多 3 种字号。超过就是信息没分层，先删信息。
- 中文不加 `text-transform: uppercase`；英文 wire value 才大写。
- 中文与数字之间留自然间距，不用全角空格凑对齐。

### 3.3 状态与分类文案

这是**显示映射**，不是新枚举。后端返回什么就映射什么。

**步骤状态**：`PENDING` 待开始 · `ACTIVE` 进行中 · `COMPLETED` 已完成 · `FAILED` 失败 · `SKIPPED` 已跳过 · `TIMED_OUT` 已超时 · `NEEDS_REVIEW` 待复核

**执行状态**：`CREATED` 已创建 · `RUNNING` 运行中 · `PAUSED` 已暂停 · `COMPLETED` 已完成 · `ABORTED` 已中止 · `NEEDS_REVIEW` 待复核

**原因码**：`EXECUTION_AMBIGUOUS` 执行歧义 · `LOW_CONFIDENCE` 置信度不足 · `EVIDENCE_MISSING` 证据缺失 · `CAMERA_CONFLICT` 相机冲突 · `LATE_EVENT` 迟到事件 · `MODEL_VERSION_MISMATCH` 模型版本不匹配 · `RULE_VERSION_MISMATCH` 规则版本不匹配 · `MANUAL_SKIP` 人工跳过 · `TIMEOUT` 超时 · `UNEXPECTED_STEP` 意外步骤 · `OUT_OF_ORDER` 顺序错误

**告警分组**：`PROCESS_COMPLIANCE` 工艺合规（单独一组）· `VISION_QUALITY` 视觉质量 · `DEVICE_HEALTH` 设备健康 · `INFERENCE_HEALTH` 推理健康 · `PLATFORM_HEALTH` 平台健康 · `CONFIGURATION` 配置（后五者属系统事实）

**证据状态**：`PENDING_VERIFY` 待校验（斜纹，不可点）· `AVAILABLE` 可用 · 其它/缺失 = 不可用（必须写原因，不得用预览帧补位）

**界面状态（本系统自定的显示词，非 wire value）**

| 词 | 含义 | 颜色 |
|---|---|---|
| 正常 | 该机位当前作业判定正确 | ok |
| 待确认 | 系统没看清，等人给结论 | warn |
| 异常 | 与 SOP 不符，且已由后端判定 | crit |
| 离线 | 没有画面信号 | off |

这四个词只描述"机位此刻"，不得用来替代步骤/执行状态的正式枚举。

## 4. 空间与布局

### 4.1 间距

`--vs-space-1..12` = 4/8/12/16/20/24/32/40/48。面板内边距 20，面板间距 14，墙体间隙 10。不用 13/18/22 这类刻度外数值；需要就先加 token 并说明。

### 4.2 屏幕骨架（1600×1000 设计稿）

| 区域 | Token | 值 |
|---|---|---|
| 顶栏 | `--vs-topbar` | 56px |
| 筛选行 | `--vs-filterbar` | 52px |
| 班次条（仅监控墙） | `--vs-shiftbar` | 52px |
| 状态栏 | `--vs-statusbar` | 30px |
| 墙体间隙 | `--vs-wall-gap` | 10px |
| 面板内边距 | `--vs-panel-pad` | 20px |
| 面板间距 | `--vs-panel-gap` | 14px |

```text
顶栏 56 ──────────────────────────────────────────────
筛选行 52 ─────────────────────────────────────────────
正文（监控墙：3 列 × 2 行画面格 / 看板：12 列栅格）────
班次条 52（仅监控墙）────────────────────────────────
状态栏 30 ─────────────────────────────────────────────
```

**栅格**

- 监控墙：`repeat(3, minmax(0,1fr))` × `repeat(2, minmax(0,1fr))`，间隙 10，padding 10，底 `--vs-void`。
- 看板：12 列，间隙 14。KPI `span 3`；趋势 `span 8` + 仪表 `span 4`；异常条 `span 5` + 表格 `span 7`。
- 墙体列数由机位数量决定（4/6/9/16），行列用 `minmax(0,1fr)` 保证画面等比压缩；不要写死像素。

**响应式**

- 桌面 1440–1600：完整布局，页面不横向滚动。
- 墙屏 1920×1080：字号 ×1.25，行高 ×1.25，画面格数增加；不要把 1600 的密度拉满到 1920。
- <1280：监控墙降到 2 列，看板面板纵向堆叠；不保证手机形态。
- 用 `min-height: 100dvh`，不用 `100vh`。

### 4.3 线、圆角、纹理

- 三层线：`--vs-grid` → `--vs-line` → `--vs-line-strong`。状态边框用语义色，不用这三层。
- **圆角一律 0**（`--vs-radius`）。面板没有阴影；浮层用 1px 边框 + 实底。
- 唯一纹理：离线画面的 135° 斜纹（11px 周期，两个近黑）。不要颗粒、噪点、网格底纹。

### 4.4 动效

| Token | 值 | 用途 |
|---|---|---|
| `--vs-motion-fast` | 120ms | hover、边框、颜色 |
| `--vs-motion-base` | 180ms | 抽屉、面板展开 |
| `--vs-ease` | `cubic-bezier(.2,0,0,1)` | 统一缓动 |

- 只动 `opacity` / `transform` / `color` / `border-color`。
- 新判定到达时，画面卡边框闪一次 120ms，不要持续脉冲。
- `prefers-reduced-motion: reduce` 下取消全部非必要过渡。

### 4.5 层级与图标

- `--vs-z-base 0 / topbar 10 / statusbar 20 / overlay 30 / dialog 40 / toast 50`。不要 9999。
- 图标 16px、1.5px 描边、`currentColor`；状态图标 12px，必须与文字成对出现。
- 图标按钮必须有 `aria-label` 与 tooltip，触摸目标 ≥44×44。
- 不用 emoji、AI 闪光、机器人头像、3D 图标。状态用几何标记（对勾/三角/叉/横杠）。

## 5. 组件语法

### 5.1 顶栏

左：16px 骨白方块字标 + 字标 `VISISOP`（78% 宽、字距 .16em）+ 竖线 + 导航（监控墙 / 看板 / 记录 / 标准）。
右：连接状态（点 + 文字，必须能区分"网关正常"与"机位有画面"）、时钟（28px 窄体）、当班用户。
当前页用 2px `--vs-ink` 下划线 + `aria-current="page"`，不用胶囊填充。

### 5.2 筛选行

左：分组标签（11px，`.1em` 字距）+ 方角 chip（30px 高，`inset 0 0 0 1px --vs-line-strong`；选中 `--vs-ink` 底 + `--vs-casing` 字）+ 竖线分组。
右：计数摘要或统计口径说明。监控墙的计数**按机位数**，且必须标 `机位` 前缀；看板与班次条**按记录数**。两种口径不能混写。

### 5.3 画面卡（监控墙的基本单元）

```text
┌ 状态章（右上）                    CAM-01 上料工位 ┐
│                                                  │
│                   画面（object-fit: cover）       │
│                   ROI 框 + 命名标签（仅需要时）    │
│                                                  │
│ ▬▬ ▬▬ ▬▬ ▬▬ ▬▬ ▬▬  2 / 6     12:41:52          │
│ 第 2 步 · 扫码上料              实时预览          │
│ 作业正确                    1920×1080 · 15 FPS    │
└──────────────────────────────────────────────────┘
```

- 整卡是一个链接/按钮，点击进入工位详情；不要在卡内放多个竞争性按钮。
- 画面必须写明**画面性质**：`实时预览` / `最后一帧` / `无信号`。三者视觉不同，不能互相冒充。
- 上下压暗层是必需的（`--vs-void` 84% → 0），否则文字会落在亮部。
- 需要人处理的卡加**处置条**（46px，实底）：待确认用 `--vs-warn`，异常用 `--vs-crit`；文案写动作 + 后果，例如"看画面并确认 · 已等 6 分钟"。
- 离线卡不显示照片：斜纹底 + 相机图标 + "没有画面信号" + 中断起始时间。
- 图片 `filter: saturate(.7) contrast(1.08) brightness(.82)`，统一成同一种画面质感。`alt` 必须描述画面内容。

### 5.4 SOP 步骤轨

- 位置：卡片底部第一行，宽度 17×5px 的段，间距 5px，后跟 `3 / 5`。
- 已走完 = `#6e7a77`；当前 = `--vs-ink`（正常）/ `--vs-warn`（待确认）/ `--vs-crit`（异常）；未到 = `#333d3f`；无信号 = 全段 `#232b2d` + `— / n`。
- 段数与序号来自后端返回的步骤总数，不得前端写死。
- 它是"做到第几步"的唯一表达，不要再配一个百分比。

### 5.5 面板

`--vs-surface` 底 + `inset 0 0 0 1px --vs-line`；内边距 20；标题行 `15px/700` + `12px` 副标题 + 右对齐口径说明；底部脚注用 `12px --vs-ink-muted` + 上边线。
面板之间靠 14px 间隙和底色区分，不靠阴影。
**不要**把每个面板做成同样大小的圆角卡；面板的高度由内容决定，栅格负责对齐。

### 5.6 指标块（stat）

标签 12px muted → 数值 46px 窄体 700 → 说明 12px。数值与标签之间留白由 `margin-top: auto` 撑开，保证同一行数值基线对齐。
需要引起注意的指标在顶部加 3px `--vs-warn` 边，不要整块染色。
**不写"合格率""通过率""效率分"。** 只写计数、时长、机位可用率这类可回溯的量。

### 5.7 状态章

`[图标 12px] 文字`，11–12px / 700 / `.06em` 字距，内边距 4×8，**方角**。
- 实底版：`ok/warn/crit` 用近黑字，`off` 用白字。用于画面卡角。
- 描边版：`inset 0 0 0 1px` 语义色 + `--vs-surface-2` 底 + `--vs-ink` 字。用于表格、列表。
颜色之外必须有图标或文字。

### 5.8 条形与仪表

- 条形：轨道 `--vs-series-track`，填充 `--vs-series`，**方角**，数值直接标在条尾，不画 Y 轴。
- 仪表（比率对目标）：轨道 8px，目标位置一条 1px 竖线；低于目标时填充换 `--vs-warn` 并加 ⚠ 图标 + 文字（不能只靠颜色）。
- 两个系列就分两张图；不要在一根条上叠两种编码。

### 5.9 表格

表头 11px / 700 / `.1em` 字距 muted，下边框 `--vs-line-strong`；行 13px，下边框 `--vs-line`。
时间列用窄体 tabular；状态列用描边状态章；证据列必须写可用性（`片段 0:12 · 缺 1 张关键帧`）。
表格本身就是图表的"表格视图"，必须能回答图表回答不了的问题（具体是哪一条）。

### 5.10 空态 / 加载 / 错误 / 过期

- 加载：骨架形状与真实布局一致，不用居中 spinner。
- 空态：说明"为什么空"和"下一步"（"当前筛选没有待处理的作业。清除筛选，或换到系统健康。"）。
- 错误：直接说发生了什么 + 重试入口；局部错误只占局部面板。
- 过期：显示"快照 10:42:08 · 已过期 32s"，此时不得再写"实时"。
- 无信号 ≠ 没有作业：离线时段不得被算成异常，也不得画成 0。

## 6. 图表规则

来自 dataviz 方法，逐条可检验：

1. **先选形，再选色。** 单一数值用指标块；趋势用线；比较用条；比率对目标用仪表；分部分用堆叠条。
2. **只有一根 Y 轴。** 两个量纲就画两张图。禁止双轴。
3. **一个色相。** 图表只用 `--vs-series`；需要区分多类时按"单色相深浅"或直接分图，不引入第二个色号。
4. **状态色不进图表。** 红/绿/琥珀在色觉缺陷下不可分辨，状态只在章、表格与进度轨上以"图标 + 文字"出现。
5. **≥2 系列必有图例，≤4 系列同时直接标注。** 单系列不要图例——标题已经说了它是什么。
6. **文字不穿系列色。** 数值、标签、图例用 ink 层级；颜色只留给图形标记。
7. **有 hover。** 线图给十字准星 + tooltip，条形给逐条 tooltip；命中区大于标记本身。
8. **有表格视图。** 每个图表都能回答"具体是哪一条"。
9. **网格与坐标轴退后。** `--vs-grid` 1px，标签 11–12px muted，不画边框。
10. **不做。** 双轴、3D、环形图、仪表盘指针、渐变发光折线、把置信度画成合格率。

## 7. 数据格式

| 类型 | 格式 | 示例 | 规则 |
|---|---|---|---|
| 绝对时间 | `YYYY-MM-DD HH:MM:SS` | `2026-10-27 10:32:08` | 本地时区；API 用 UTC；状态栏标时区 |
| 时间（紧凑） | `HH:MM:SS` | `10:32:08` | 同一天内；悬停给完整值 |
| 时长 | `12 分 08 秒` / `1 小时 04 分` | `15 分 28 秒` | 不四舍五入成"约 15 分钟" |
| 执行 ID | `EXE-####` | `EXE-1838` | 大写，不缩写 |
| 机位 / 工位 | `CAM-01` / `ST-03` | `CAM-03` | 不翻译 ID |
| SOP 版本 | `SOP-<name> v<n>` | `SOP-SEAT-04 v3` | 版本必须与执行一起出现 |
| 哈希 | `sha256:xxxxxxxx…` | `sha256:ab12cd34…` | 列表截断 8 位；详情可复制完整值 |
| 置信度 | `0.71` + 阈值 + 模型版本 | `0.71 / 0.92 · yolo-seat v4` | **不用 `%`，不写"合格率"** |
| 计数 | 精确整数 | `3` | 不写"约" |
| 不可用 | `不可用` + 原因 | `不可用 · 待校验` | 不用空白或 0 代替 |
| 不适用 | `—` | `第二视角 —` | 与"不可用"区分，并有 tooltip |

## 8. 可访问性

- 正文 ≥4.5:1，大字/图形 ≥3:1；装饰线不承担唯一信息。§2.4 是实测值。
- 焦点可见：`--vs-focus-ring`。不用 `outline: none`。
- 跳过导航；路由切换后焦点落到页面标题；抽屉关闭后焦点回到触发点。
- 监控墙可键盘走查：`←/→` 切换画面格，`Enter` 打开，`Esc` 返回。
- 表格有表头关联；状态章有可读文本，不只颜色。
- 200% 缩放不横向溢出；`prefers-reduced-motion` 下禁用过渡。
- WS 状态用 `aria-live="polite"`，不要每次心跳都播报。

## 9. 做 / 不做

| 做 | 不做 |
|---|---|
| 画面占满、文字压暗层、分辨率角标 | 手绘 SVG 假装是相机画面 |
| 一屏一个主体 | 每屏 6 个 KPI 卡 |
| 方角 + 1px 线 + 底色分层 | 圆角卡片 + 阴影 + 渐变 |
| 信号色只落在状态上 | 品牌色、标题装饰也用琥珀 |
| 一条轴、一个色相 | 双轴、红绿多系列、环形合格率 |
| 状态 = 图标 + 文字 | 状态 = 只有颜色 |
| 缺证据就写缺证据 | 用预览帧或占位图补位 |
| 精确整数与时长 | "99.9%""约 15 分钟" |
| 直接、具体的错误文案 | "Oops""出错了呢" |
| 静态、可键盘操作 | 呼吸灯、扫描线、数字滚动 |
